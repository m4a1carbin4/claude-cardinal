한눈에 요약

Claude Code 세션 여러 개를 tmux로 띄우고, 서로 일을 시키고, 디스코드 같은 외부 채널 메시지를 세션에 넘겨 답하게 하는 오케스트레이터.

돌아가는 것: 세션 생성/제어/상태 확인 CLI (작업 폴더는 기본 고정, 세션별 지정 가능), 마스터가 워커를 띄워 일 시키기, 웹 터미널, 세션 기록 SQLite, 채널 라우팅(local 채널로 끝까지 검증), 세션 안 에이전트의 직접 답장(텍스트·파일), 자동 답장.

최근 집중한 것: 동시성과 상태 판정. 같은 세션에 메시지가 겹치면 합쳐지던 문제, 같은 이름 세션 꼬임, 막 뜬 세션의 Enter 먹힘, Esc 중단 뒤 멈춤, 트랜스크립트 턴 오판을 실제로 재현하고 고침. 서버 중복 실행도 시작 전에 막음.

남은 것: 높음·중간 이슈는 없음. 낮음 3건(동시 훅 덮어쓰기, Enter 3회 실패 시 입력창 잔여, 붙여넣기 감싸기)과, 디스코드 실제 봇 연동 등 미검증 항목. 한 번에 보낼 수 있는 텍스트가 16,000바이트인 건 tmux 제약이라 안내 사항으로 둠.

시스템 구조

세션 제어 로직은 TS CLI 한 곳. 서버는 CLI를 부르고 파일을 DB로 모으는 역할. 훅은 자기 전용 폴더에만 씀.

지금 동작하는 기능

각 기능 아래 "확인"은 실제로 돌려서 본 결과.

세션 생성 · 관리 동작

  • cardinal new — claude를 tmux로 띄움. 작업 폴더는 기본 고정 워크스페이스, --cwd(API cwd)로 세션별 지정
  • 기록(meta·훅)은 작업 폴더와 상관없이 항상 ~/.cardinal 아래
  • 처음 쓰는 폴더의 신뢰 다이얼로그 감지, --trust로 자동 수락
  • 세션 고유 키(instanceId)마다 전용 훅 폴더
  • 같은 이름 동시 생성 → 이름별 락으로 하나만 성공
  • tmux 실패 시 meta·훅 폴더 롤백
확인: 같은 이름 5개 동시 → 1개 생성, 4개 거부 · 이름 재사용·/clear·purge 꼬임 없음 · 커스텀 폴더(상대 경로·/tmp 링크 포함)에서도 같은 회귀 테스트 통과

명령 하달 (send) 동작

  • 세션 락으로 한 줄로 세움 (CLI·서버·마스터 공통)
  • 작업 중이면 idle 대기 → 메시지 하나 = 턴 하나
  • 막 뜬 세션 1.5초 대기, Enter 최대 3회
  • --wait는 자기 턴의 답만 반환
  • 16,000바이트 넘는 텍스트는 tmux에 넘기기 전에 안내와 함께 거부
확인: 0~0.2초 간격 동시 send 분리 · 이벤트 2개 0.1초 간격 → 턴 2개 · 세션 4개 동시 + 이벤트 6개 2라운드 전부 정상

상태 확인 · 결과 보고 동작

  • 훅 기반 상태: starting / idle / busy / waiting / ended
  • Esc 중단은 사람 개입으로: idle + Interrupted, 기다리던 쪽 즉시 종료
  • report: 살아있나 + 작업중/완료/중단 + 마지막 사람 턴 전체 응답
  • 파서: 사람 입력만 턴 (백그라운드 알림·명령 줄·요약 구분)
확인: Esc 1초 안에 send --wait 종료, 다음 send 1초 · 알림 턴이 생겨도 사람 턴 답 유지

마스터 → 워커 동작

  • 마스터는 서브 에이전트 대신 독립 tmux 세션으로 일을 나눔
  • CLI 절대경로를 시스템 프롬프트에 박음 (PATH 문제 해결)
확인: 마스터가 워커를 띄우고 → report로 전체 응답 회수 → kill

서버 · DB · 웹 터미널 동작

  • FastAPI: REST, /ws/term, /ws/events, /ws/channel, /api/health
  • SQLite: 세션·훅 이벤트·라우트·채널 이벤트·전달·답장
  • purge해도 DB 기록 유지, 서버 꺼진 동안 기록도 따라잡음
  • 시작 전 중복 실행·포트 확인 (server.json 보호)
확인: 파일 56줄 = DB 56행 · 웹 터미널 20회 열고 닫아도 fd/pty 누수 없음 · 토큰 인증

메시지 채널 · 답장 부분

  • 라우트: 채널명 + 트리거 (prefix/contains/regex/멘션)
  • 첨부파일 inbox 저장 → 에이전트가 읽음
  • cardinal reply (텍스트·파일), auto_reply
확인: local 채널로 끝까지 동작 · 디스코드는 실제 봇으로 미검증 (토큰 없음, 잘못된 토큰 감지는 확인)

핵심 흐름

디스코드 메시지 하나가 세션에 들어가 답장이 나가기까지.

  1. 봇이 메시지를 받음 (봇 메시지는 무시) → channel_events에 저장
  2. 살아있는 세션의 라우트와 매칭 → 맞으면 첨부파일을 ~/.cardinal/inbox/<이벤트>/에 받아둠
  3. 전달 기록 pending → 서버 세션 락 → CLI send (세션 락 → idle 대기 → 붙여넣기 → Enter → 수신 확인)
  4. 세션 안 에이전트가 [cardinal:event …] 메시지를 보고 작업
  5. 에이전트가 cardinal reply <이벤트> "…" --file … → 서버가 원래 메시지에 답장 (2000자 분할, 파일 10개씩)
  6. auto_reply면: 턴 종료 + 트랜스크립트 기록까지 기다린 뒤, 아직 아무도 답 안 했으면 마지막 응답으로 자동 답장
실측 타임라인 예: 수신 → 전달 약 0.3초, 에이전트가 첨부 읽고 답장까지 약 12초. 자동 답장은 Stop 후 약 0.5초.

해결한 문제

대부분 실제로 재현한 뒤 고치고, 같은 조건으로 다시 돌려 확인함.

영역문제해결
동시성같은 세션에 0.2초 안에 들어온 send가 한 입력으로 합쳐짐세션 파일 락으로 직렬화
동시성작업 중에 보낸 메시지가 진행 중인 턴에 끼어듦기본 idle 대기 (--now로 예외)
동시성--wait가 다음 턴(남의) 답을 가져감보낼 때 턴 위치 기억 → 자기 턴만
동시성같은 이름 동시 생성 → 세션이 영원히 starting이름별 생성 락 + 목록 확인
동시성락 경합 / pid 재사용잡은 시각 기록, 30분 초과 stale, 지우기 전 재확인
정체성이름 재사용 시 이전 세션 훅이 새 세션 오염instanceId별 훅 폴더 (경로를 훅 명령에 박음)
정체성/clear 뒤 옛 트랜스크립트를 읽음훅이 최신 claude 세션 ID 추적
정체성purge 뒤 늦은 훅이 폴더를 되살림훅·저장소가 폴더를 안 만듦
정체성tmux 실패해도 meta가 남음롤백
전달막 뜬 세션에서 Enter가 먹혀 900초 멈춤1.5초 대기 + Enter 3회 + 못 받으면 즉시 실패
전달Stop이 마지막 답 기록보다 먼저 와서 자동 답장이 빔턴이 end_turn으로 기록될 때까지 최대 5초 대기
전달starting 세션 전달이 즉시 실패pending으로 기다렸다 전달
전달신뢰 다이얼로그에 걸린 세션으로의 전달이 600초 pending다이얼로그 감지 → 즉시 실패 + 이유, --trust로 자동 수락
전달--wait 타임아웃을 전달 실패로 기록timedOut으로 구분, 기록은 sent
전달auto_reply 중복 (다른 세션이 답했을 때)이벤트 단위로 답장 여부 확인
전달외부 본문의 제어 문자탭·줄바꿈 외 제거
상태Stop 뒤 정체불명 PreToolUse로 busy 고착턴 밖 도구 이벤트 무시
상태Esc 중단 뒤 busy에 멈춰 wait/send가 최대 600초 막힘사람 개입으로 처리 (트랜스크립트의 중단 표시 감지)
상태백그라운드 작업 알림 턴의 답이 "마지막 턴"으로 나옴알림 턴은 사람 턴으로 안 셈
결과파서가 /clear·/compact·요약 줄을 턴으로 봄 (예: 9턴 → 실제 1턴)사람 입력만 턴 시작
결과last가 마지막 텍스트 블록 하나만 가져옴턴 단위 파서 + report
서버서버를 겹쳐 띄우면 살아있는 서버의 server.json이 지워짐시작 전 중복 실행·포트 확인
서버잘못된 디스코드 토큰이 무음 실패에러 로그 + /api/health
서버로그에 ?token= 노출token=***로 가림
서버느린 웹소켓 구독자가 전달을 붙잡음동시 전송 + 2초 제한
서버/ws/events가 3초마다 의미 없는 푸시실제 변화 있을 때만
서버/send wait 무한 대기, 답장 API 무제한기본 900초, 400/413 검사
기타마스터 세션이 cardinal을 못 찾음 (PATH)시스템 프롬프트에 절대경로
기타node-pty 실행 권한 / Node 서버Python 서버로 이전하며 해소

남은 문제

높음·중간 이슈는 없음. 재현 = 실제로 돌려서 확인 · 코드 = 코드만 보고 판단.

구분항목내용확인대응
낮음 같은 세션 안 동시 훅끼리 state.json 덮어쓰기 실측상 겹치는 건 같은 목표 상태끼리뿐 (목표가 다른 이벤트 간 최소 간격 1.4초) 재현(원리) 필요해지면 이벤트 로그로 상태 계산
낮음 Enter 3회 모두 실패하면 텍스트가 입력창에 남을 수 있음 다음 send와 섞일 여지. 1.5초 대기 도입 뒤로는 재현 안 됨 코드 실패 시 입력창 비우기
낮음 전달 메시지가 <pasted_content>로 감싸짐 붙여넣은 내용 속 지시를 모델이 덜 믿을 여지. 지금은 문제 없음 관찰 지켜보기
안내 한 번에 보내는 텍스트 16,000바이트 한도 tmux가 명령 하나로 받는 크기 한도 (실측 16,343바이트). 한글 약 5,300자 재현 tmux 제약이라 따름. 넘으면 사전 안내, 긴 내용은 파일 경로로
범위 밖 서버 재시작 시 auto_reply 대기 소실, cardinal reply 재시도 없음 서버 운영은 사용자 몫 코드 —
